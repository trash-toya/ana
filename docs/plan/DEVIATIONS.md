## Things we accept as-is and will not "fix"

| Item                                              | Position                                                                                                                                                                                                                                                    |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No foreign keys on `events`                       | Correct for an append-only hot path; replaced by periodic integrity checks (I8).                                                                                                                                                                            |
| `event_dedupe` as a plain table with a global key | Correct; it is the only way to be race-free across midnight. Generation tables are a P5 option, not a correction.                                                                                                                                           |
| No `COMMIT` inside job procedures                 | Correct; each run is one bounded transaction and at-least-once execution is idempotent.                                                                                                                                                                     |
| Client-minted session/event IDs                   | Correct; the client is the only component that sees the person leave and return. The embedded UUIDv7 timestamp is never trusted.                                                                                                                            |
| 3-day guard/dedupe retention                      | Correct: 24 h event age + 24 h max session + 1 day margin.                                                                                                                                                                                                  |
| Approximate visitor/user counts                   | Correct and labelled; HLL at 4,096 buckets is ~1.6% error and rollups need the sketch.                                                                                                                                                                      |
| Rate limits in process                            | Correct at the current few-instance scale, but per-key limits are per instance (N× the configured value). Per-session and per-IP limits are exact under consistent-hash routing; per-key limits move to a Postgres counter before more instances are added. |

Bugs found and fixed during the migration (previously hidden because the new
`packages/sdk-web/test/retry.test.mjs` could never finish):

1. `selectBatch` compared against the `MAX_EVENTS_PER_REQUEST` **constant** instead of the
   `maxEvents` parameter, so the 413-halving in the flush loop never shrank the batch, and a
   single oversize event spun the loop forever. The server SDK's copy was already correct.
2. The retry-matrix test expectations assumed the queue depth after one `track()` is 1 and
   the first batch is 2 events; a fresh session actually mints 3 events (session_start,
   page_view, trigger) and the first attempt is the full queue. Fixed with comments.

Calendar rot in the DB suite (found when T1 started failing for no code reason): invariants
I3 and I8 have time windows (`created_at − 24 h`, `now() − 3 days`), and T1/T6/T9 hardcoded
event dates of 2026-11-15, which drift out of those windows as the calendar advances. The
harness now exports `recentBase()` and all three suites anchor their fixture times to it.
